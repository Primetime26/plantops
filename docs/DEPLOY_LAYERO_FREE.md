# PlantOps на Layero Free — один сервис, 0 ₽/месяц

Документация проверена **12 ноября 2026**. Это инструкция для самостоятельной публикации. В ходе разработки деплой и git push не выполнялись; успешная локальная сборка не является проверкой инфраструктуры Layero.

## 1. Выбранная архитектура

Один Node runtime в корне монорепозитория. Express отдаёт `/api/*` и `apps/web/dist`; история маршрутов SPA поддерживается. Нужен один адрес `*.layero.app`. React обращается к относительному `/api`, поэтому отдельные адрес API, CORS и переменные `VITE_API_URL` не нужны.

Free включает runtime и адрес платформы; отдельные PostgreSQL, Redis, домен, банковская карта для внешних сервисов проекту не нужны. Не включайте Pro или платные базы. [Тарифы Layero](https://docs.layero.ru/billing/plans/).

Public Demo работает **в памяти одного процесса**. Между перезапусками/перемещениями на другой pod данные не сохраняются; приложение сообщает о сбросе. Это предусмотренный компромисс бесплатного интерактивного стенда. Постоянная SQLite остаётся только в Local Mode. [Stateless-инвариант](https://docs.layero.ru/runtime/stateless).

## 2. Сначала проверить код локально

Из корня существующего проекта:

```sh
npm ci
npm run setup
npm run typecheck
npm test
npm run build:demo
npm run check:resources
npx playwright install chromium
npm run test:e2e
npm run start:demo
```

Открыть `http://127.0.0.1:3001`. `start:demo` не использует рабочую SQLite и не меняет `apps/api/.env`. Для остановки — Ctrl+C. Тестам Playwright нужны свободные порты 3100 и 3101.

Перед публикацией самостоятельно проверьте изменения и отправьте их в GitHub. Не загружайте `.env`, `node_modules`, `work`, файлы БД, результаты тестов. `package-lock.json`, миграции и `layero.json` должны быть в Git.

## 3. Подключение GitHub

В Layero войдите в аккаунт с тарифом **Free**, подключите GitHub App и предоставьте доступ к выбранному репозиторию `Primetime26/plantops`. Затем создайте проект через импорт из GitHub и выберите ветку `main`. Доступ ко всем репозиториям не нужен. [Официальное подключение Git-провайдеров](https://docs.layero.ru/deploys/git-providers).

## 4. Монорепозиторий: что выбрать на экране импорта

**Нужен один проект из корня репозитория (`.`)**, содержащего `package.json`, `package-lock.json`, `apps/`, `packages/` и `layero.json`.

Если интерфейс предлагает отдельные `api / Express` и `web / Vite`, это автоопределение двух workspace-приложений. Для нашей схемы не публикуйте их как два независимых проекта. Перейдите к настройке единственного Node-приложения и задайте корень репозитория. Названия полей могут отличаться; проверяйте фактический рабочий каталог в настройках/логе сборки. Если импорт уже создан для `apps/api`, измените корневой каталог проекта перед сборкой.

Почему это необходимо: backend использует общий пакет `@plantops/contracts`, а сборка из корня создаёт оба `dist`. Корень `apps/web` опубликует только интерфейс без серверных операций; корень `apps/api` лишит сборку нужного workspace-контекста.

## 5. Сборка и запуск

Конфигурация закреплена в корневом `layero.json`, чтобы её можно было проверять вместе с кодом:

| Параметр                   | Значение                                                                       |
| -------------------------- | ------------------------------------------------------------------------------ |
| Корень приложения в панели | `.`                                                                            |
| Фреймворк сборки           | `generic`                                                                      |
| Тип runtime                | `node_web`                                                                     |
| Установка                  | `npm ci` по корневому lock-файлу                                               |
| Сборка                     | `npm run build:demo`                                                           |
| Запуск                     | `node --max-old-space-size=128 --max-semi-space-size=4 apps/api/dist/index.js` |
| Порт                       | `3000`                                                                         |
| Адрес прослушивания        | `0.0.0.0`                                                                      |
| Память                     | базовые `256` МБ                                                               |
| Предзагрузка               | `false`; без keep-alive и внешних пингов                                       |

`outputDirectory` не нужен для Node runtime: Express сам находит frontend. `rootDirectory` не является ключом нашего файла — корень выбирается в панели. В Node runtime Layero выбирает установку по lock-файлу; отдельный `installCommand` в `layero.json` не используется. [Формат конфигурации](https://docs.layero.ru/deploys/layero-json).

Рекомендуется Node 24 (протестирован локально); современный Node 22.12+ подходит для приложения, измеритель памяти использует `registerHooks`, доступный в Node 22.15+/24. Сборке нужны devDependencies (TypeScript, Vite, Prisma CLI): не используйте `npm ci --omit=dev` до сборки. Prisma Client генерируется для компиляции локального адаптера, но **Prisma не импортируется и движок не запускается в demo runtime**. Миграции и seed в облаке не выполняются.

## 6. Переменные окружения

Указаны в `layero.json` и не являются секретами:

| Имя                  | Значение     | Назначение                                                                        |
| -------------------- | ------------ | --------------------------------------------------------------------------------- |
| `APP_MODE`           | `demo`       | Серверное временное хранилище                                                     |
| `NODE_ENV`           | `production` | Secure-cookie для HTTPS                                                           |
| `HOST`               | `0.0.0.0`    | Доступность внутри контейнера                                                     |
| `PORT`               | `3000`       | Совпадает с конфигурацией runtime                                                 |
| `TRUST_LAYERO_PROXY` | `true`       | Для ограничения частоты запросов использовать выставленный платформой `X-Real-IP` |

Не задавайте `DATABASE_URL`. Не переносите локальный `.env` в облако. `TRUST_LAYERO_PROXY=true` допустим только за доверенным прокси Layero; при прямом локальном запуске оставляйте `false`. [Требования runtime и адрес клиента](https://docs.layero.ru/runtime/overview).

## 7. Проверка после публикации

1. Откройте выданный HTTPS-адрес: должна загрузиться главная панель, пять единиц и уведомление о временных данных.
2. Откройте `/api/health`: ожидается `{"status":"ok","mode":"demo","demo":true}`.
3. Прямо откройте `/equipment/H-101`, обновите страницу — SPA-маршрут должен работать.
4. Запустите перегрев. Через примерно 15–30 секунд активного просмотра появится предупреждение/критическое состояние и один инцидент температуры.
5. Подтвердите, затем восстановите режим — событие станет `RESOLVED` и останется в текущей истории.
6. Создайте заявку, возьмите в работу, укажите результат и завершите.
7. Откройте отдельное приватное окно: его состояние должно быть независимым. Вкладки одного браузерного профиля намеренно делят cookie и сессию.
8. Сбросьте демо: заявки и история вашей сессии исчезнут, другие посетители не затронуты.

При холодном старте React показывает подготовку сессии, через 4 секунды уточняет ожидание; запрос ограничен 45 секундами, затем доступен повтор. До получения самого HTML интерфейс ещё не может отрисоваться: возможная стартовая страница/404 Layero контролируется платформой. Если она сохраняется дольше минуты, проверьте корень, команду, порт и сборку. [Проверка готовности runtime](https://docs.layero.ru/runtime/overview).

## 8. Сбросы и лимиты приложения

- До **10** гостевых сессий на процесс; заполненный стенд отвечает 503 с `Retry-After`.
- Сессия удаляется после 15 минут без запросов либо через 1 час с создания; очистка выполняется при следующем обращении, без фонового таймера.
- В сессии: 360 последних показаний на единицу, 100 инцидентов, 20 заявок (включая архив), 10 комментариев и 40 последних записей истории на заявку.
- При заполнении журнала вытесняются старые устранённые события; активные не теряются. История заявки в demo — ограниченное окно, не постоянный аудит.
- Симуляция по серверному времени при запросе, шаг 5 секунд, не более 12 догоняющих шагов. Длительные пропуски не восстанавливаются полностью.
- Скрытая вкладка и вкладка без действий 2 минуты прекращают polling. Это не keep-alive; кнопка продолжения возобновляет просмотр.
- После потери состояния API возвращает `SESSION_RESET`; клиент получает новую cookie и ревизию, сбрасывает старые формы/данные. GET можно повторить, изменение автоматически не переигрывается.

Один процесс рекомендован. При частом переключении между несколькими pod сессия может сбрасываться повторно. Без общего внешнего хранилища здесь нет обещания устойчивой multi-pod сессии; этот сценарий нужно проверить после размещения в вашем аккаунте.

## 9. Как контролировать бесплатное потребление

Откройте организацию → **Потребление**, проверьте тариф, период и расход проекта. На дату проверки страница лимитов помечена **«Черновик»**: опубликованы ориентиры Free — 100 сборок, 300 минут сборки, 15 ГБ, 300 тыс. запросов, 6000 взвешенных runtime-минут. Документ прямо говорит, что ограничения пока не применяются и могут измениться. Проверяйте актуальное состояние перед публикацией, не обещайте доступность 24/7. Базовая конфигурация учёта — 0,25 vCPU / 256 МБ. [Потребление и лимиты](https://docs.layero.ru/billing/usage).

Проект не подключает платные услуги автоматически. Для бюджета 0 ₽ оставайтесь на Free, не включайте внешние базы, усиленный runtime, предзагрузку и оплату сверх тарифа. При ограничении бесплатного доступа дождитесь обновления периода; оплата не является технической зависимостью PlantOps.

Локальное измерение: `npm run check:resources`. Оно заполняет все разрешённые сессии и объекты, выполняет конкурентные запросы, блокирует загрузку Prisma и проверяет пик RSS <230 МиБ. Результат относится к данной ОС/Node; фактический контейнерный расход и CPU нужно подтвердить на Layero. Платные средства мониторинга для работы приложения не требуются; бесплатная диагностика ограничена доступными экраном потребления, статусами сборки и health endpoint.

## 10. Обновления

Проверьте изменения локально, самостоятельно сделайте commit/push в production-ветку. Layero запустит сборку по вебхуку. Сверьте SHA и статус, повторите smoke-сценарий. Каждый новый runtime начинает демосессии заново. Ограничьте ненужные preview-сборки, чтобы не расходовать бесплатный бюджет.

Если ошибка повторяется, сначала исправьте её причину; не запускайте серию одинаковых сборок. При необходимости откатите код к проверенному коммиту и выполните новую сборку.
